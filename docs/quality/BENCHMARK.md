## 首版评测口径（待实测）

### Agent 记忆对照（待实测）

对同一组有授权的合成历史固定资料、时间、模型、Prompt、工具和题目。分别跑关闭跨会话召回、开启召回、开启召回并压低上下文预算三组。使用项目的 12 个验收场景验证工程边界，再按信息提取、跨会话推理、时序、更正、无答案各准备至少 3 个冻结问题，共至少 15 题。可以复用资料与标注，单独统计记忆题。每个真实配置至少运行两轮，报告逐轮分子、分母、失败样例与总用量。小样本只用于版本回归。

首版拟定目标为开启召回后每轮至少 12/15 题答对（扩充时按 ≥80%），每类至少答对两题。压缩组另须保留全部预先标注的硬约束和证据锚点，记录触发次数、请求 token 估计与可得实测、端到端延迟、额外模型调用及成本。不相关召回、无依据回答、权限泄漏分别记录；越权暴露、已撤销记忆被重新注入、超预算仍提交和重复发布成果均阻断验收。模型不可用时保留离线结果，真实质量项标为待验。

### 后端容量与研究策略对照（待实测）

1. 在独立 PG 库生成固定种子的 1 万及 10 万条资料元数据，标明工作区分布、时间戳重复比例和查询条件。对首、中、末页保存 offset 与游标方案的结果、耗时及只读查询的 EXPLAIN (ANALYZE, BUFFERS)。冷热结果分列，记录测试机和版本。
2. 同时运行资料读取与索引提交。用离线夹具固定模型响应时间，分档提高并发到超过配置额度，分别记录读请求、入队响应、排队等待和执行时间。每档保存并发上限、持续时间、吞吐、延迟分位、超额与服务繁忙响应、积压峰值和排空时间。对照调节一个参数，核验权限、任务唯一发布及恢复后可读。真实模型只做受预算控制的小样本验收。
3. 冻结同一批单来源、跨来源、冲突和无答案题及初始证据范围，在同一模型、相同最大预算下对比固定 RAG 与工具型 Agent。记录逐题任务成功、引用支持、工具次数、token、耗时与失败阶段。额外调用的收益按题型复核，成本按所有尝试统计。保留失败记录和修复前后配置，冻结验收题不参与调参。

### RAG 质量门槛

调试用样例与最终验收集分别维护。验收集至少 40 题，其中至少 10 道无答案，覆盖中文文档、字幕和需要两份来源的问题。每题事先标注应回答或拒答、预期结论及可替代的证据片段。文本与向量方案共用资料版本、检索范围和题目。冻结后修改模型或提示词，保留前后两轮记录。

| 指标 | 计算与判断 |
| --- | --- |
| Recall@5 | 每道可回答题计算前五条命中的必需证据组数除以全部必需组数，再取宏平均。组内任一等价片段即可命中。目标 ≥80% |
| 引用与回答 | 已回答题中，所有关键结论均有可定位且支持结论的证据才计为通过，目标 ≥90%。另要求可回答题中获得有据正确答案的比例 ≥80%，将过度拒答、空答和运行错误计入失败。无答案题正确拒答率目标 ≥90% |
| 工作流与运行成本 | 预先标记每个任务的预期终态，包括正常完成、拒绝和受控失败。分别报告业务成功率、预期终态符合率、越权拦截和每次尝试的用量。供应商未回报的用量标为未知。按固定环境报告样本数、冷暖启动、成功延迟 P50/P95 与超时数 |

## 2026-11-21 · 单字幕词面召回基线

在 Windows、Eclipse Adoptium Java 21.0.12.1、Maven 3.9.11 上，使用 [42 道合成题](../../sample-data/retrieval/transcript-v1/questions.json)和两份合成 SRT（14 与 13 个片段）。每题限定一份资料。评测直接调用生产字幕解析、版本化证据构造和 Java Top 5 召回。评测没有启动数据库和 HTTP 服务，也没有调用模型。两次运行的逐题输出一致。[逐题基线 JSON](results/transcript-v1-lexical.json)

2026-11-23 用同一冻结题集对比跨资料候选入口的两种实现。在独立 PostgreSQL 17.12 上，按该入口每份最多两条的规则，数据库索引与 Java 扫描的证据 ID、正文、坐标和顺序 **42/42 一致**。这个实验验证迁移等价性，原 Top 5 指标仍见下表，规模与性能另外测量。

| 题型 | 全部证据组命中的题 | 无候选的题 | 宏平均 Recall@5 |
| --- | ---: | ---: | ---: |
| 原词 | 12/12 | 0/12 | 100% |
| 同义改写 | 5/12 | 5/12 | 41.7% |
| 同一资料的多证据 | 6/6 | 0/6 | 100% |
| **全部可回答题** | **23/30** | **5/30** | **76.7%** |
| 含相关术语的无答案题 | 不适用 | 0/6 | 不适用 |
| 无关主题的无答案题 | 不适用 | 6/6 | 不适用 |

每题含一个或多个必需证据组。命中组内任一等价片段即覆盖本组。先以该题覆盖的组数除以必需组数，再对可回答题取平均。无答案题的无候选比例为 6/12，是检索层的观测值。最终拒答还取决于后续模型。

- `P05-P` 用「翻页从哪里续接」替换「游标分页」，漏掉后端第 12 段，没有召回候选。
- `P08-P` 用「新检索库做坏了」概括索引构建失败，检索返回索引第 2、6、12 段，漏掉目标第 3 段。
- `D01` 问评论缓存用 Redis 还是 Memcached，检索找到后端第 1、2、3 段。它们描述缓存行为，未说明产品选型。

从仓库根目录运行。每次新的逐题结果写入构建目录，归档 JSON 保留为本轮快照。

```powershell
mvn.cmd -o -B -f server/pom.xml "-Dtest=TranscriptRetrievalBenchmarkTest" test
Get-Content -Raw -Encoding utf8 server/target/transcript-retrieval-v1.json
```

本轮单字幕合成基线为 76.7%，低于项目的 80% 参考线。后续先用该数据对比同义召回，再用独立的中文文档、跨资料和真实模型题集做发布验收。真实模型回答率、拒答率、性能和成本待测。

## 2026-11-23 · pgvector 精确排序对照

独立 PostgreSQL 17.12 Debian、pgvector 0.8.7。复用同一 BGE 向量、两份冻结题及 512 维向量。SQL 先限制工作区、资料 ID、原文版本和模型权重指纹，再按精确余弦与原文次序取 Top 5。结果分别 42/42、12/12 题与内存计算一致，最大分差约 1.27×10⁻⁷。维度错误被数据库以 SQLSTATE `22000` 拒绝。在每份题集加入四个与查询向量相同的干扰项，各改变一个范围字段，正常结果均未返回干扰项。该实验检验 SQL 范围条件，应用身份授权另测。 [pgvector 精确搜索文档](https://github.com/pgvector/pgvector#querying)

本机回环数据库调用 P50/P95 为 2.01/2.59 ms（42 题）与 2.05/3.97 ms（12 题）。这包含驱动、回环和执行，未包含向量编码或真实应用流量。未引入近似索引，未比较吞吐。 [逐题报告](results/pgvector-parity-v1.json)
