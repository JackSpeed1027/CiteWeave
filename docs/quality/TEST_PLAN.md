## 发布候选的故障验收

### 研究 Agent 专项验收

在独立测试工作区放一份合成设计文档和一条字幕，标注两个有分歧的结论、一项限制条件及一项资料无法回答的问题。准备 A、B 两名用户和两个工作区，使用可控模型夹具注入异常，另用固定的真实供应商配置跑业务演示。以下 12 个场景进入既有 Agent 用例集。

| 场景 | 操作和通过条件 |
| --- | --- |
| 1. 工具决策 | 真实模型收到两种工具定义，跨来源问题触发检索及证据读取，能按调用 ID 对应真实返回，答案可跳回两处原文。 |
| 2. 短期记忆 | 第一轮列出两个分歧，刷新并追问第二点。回答匹配第二项和原引用；不相关会话不能混入。 |
| 3. 跨会话续研 | 确认一个未决问题，重启服务并开新会话，能找回问题、来源和时间；未确认候选不会作为已确认事实召回。 |
| 4. 更正与时序 | 连续确认、更正同一结论，分别询问当前值及先前讨论。当前只采用生效修订，历史回答表明时间和证据。 |
| 5. 撤销 | 已召回的记忆生成快照后撤销。新会话与恢复运行均须排除撤销项及其派生提示，历史笔记可依原权限打开。 |
| 6. 连续压缩 | 固定较低窗口，触发至少两次自动压缩。记录完整请求预算，逐项核对用户约束、两个分歧、未决问题、引用及工具请求与返回配对。 |
| 7. 压缩失败 | 注入摘要超时、坏引用和超长当前问题。验证快照未被坏结果替换，回退后仍超限则停止调用并保留研究进度。 |
| 8. 隔离与撤权 | 在工具执行或任务恢复前撤销资料权限。检查测试模型的实际入参、回答、导出均不含被撤权片段；同用户跨工作区、同工作区跨用户的私有记忆均隔离。 |
| 9. 不可信资料 | 资料内放入要求永久记住无关内容的合成文本。只将其作为资料，验证无自动确认记忆、越权查询或外部写入。 |
| 10. 幂等与恢复 | 重复提交一轮，在已持久化工具结果后中断再恢复。只有一个最终回答，已完成步骤可追溯，模糊的上游结果显示用量未知。 |
| 11. 取消与耗尽 | 分别触发用户取消、工具循环、错误参数及预算用尽。运行有限终止，迟到响应不能发布答案，UI 能查看原因和已完成步骤。 |
| 12. 缺证拒答 | 注入与当前原文冲突的历史记忆，并提出无答案问题。有依据时回查并指出冲突，缺依据时拒答，不能用记忆代替引用。 |

依次在 CI 运行离线契约与确定性故障用例，在隔离 PG 和正式 Web 跑跨进程集成，在发布候选上跑真实工具、跨会话及自动压缩三条路径。记录版本、配置、脱敏轨迹和失败分母。用户从正式 Web 亲自完成“追问 → 确认 → 新会话续研 → 撤销”，写下实际观察。

### 资料与服务故障验收

以下资料溯源场景随首次联合交付和索引发布分别验收，样例使用独立工作区。

| 时点 | 操作 | 通过条件 |
| --- | --- | --- |
| 字幕摘要联调 | 让两份资料含相同时间区间及相同片段序号。打开第二份资料的摘要引用，再刷新页面 | 仍能回到第二份资料的对应版本、轨道和原句，引用身份不依赖显示顺序 |
| 摘要预算裁剪 | Java 提供 A、B 两条证据，Python 因预算只发送 A，用夹具返回引用 B 的草稿 | 可从测试记录核对实际输入只有 A。拒绝草稿，资料仍可读，无成功回答或笔记被发布 |
| 索引换代 | 对同一文档改变切块大小后重建索引，分别打开旧笔记和新回答 | 两者均可按各自的资料版本定位；旧笔记无需持有旧向量索引。撤权后无法读取原句 |

使用独立 Compose 项目、独立卷和有标记的样例。以下均为待执行用例。保存运行版本、输入、期望与实际结果，以及请求或任务 ID。

| 场景 | 操作 | 可观察的通过条件 |
| --- | --- | --- |
| 用户未收到提交回执 | 同一用户用同一请求键再次提交同一研究任务，随后刷新页面。再用相同键提交不同问题 | 前两次返回同一任务且成果仅保存一次。冲突载荷有明确错误。旧版普通资料导入仍遵循原有 HTTP 契约 |
| 旧 worker 晚于新 worker 完成 | 暂停已领取任务的 A，让租约过期，由 B 领取并发布，再恢复 A。另测构建期间资料更新 | A 的提交被拒。始终只见完整发布版本。历史笔记打开原始证据，运行轨迹能解释每次尝试 |
| 模型限流或返回坏引用 | 分别注入 429、超时和不属于本批的引用，刷新页面后打开已有成果 | 重试受预算约束，失败可追踪，原资料可读，已有笔记可导出。坏草稿不能成为正式成果 |
| 跨工作区研究 | 在工作区 B 放入独有标记，用工作区 A 身份发起搜索、读取、恢复任务、导出笔记，再核对发给模型的证据 | 模型入参、客户端结果和导出均不含 B 的标记。恢复时重新检查权限，拒绝记录可按任务追踪 |
| 从备份恢复一个研究工作区 | 对停写的测试工作区备份数据库与受控文件，恢复到另一组空白测试卷，重新登录并打开笔记和引用 | 资料、轨道、笔记、文件摘要和引用定位可与备份清单核对，恢复耗时有记录。可重建索引完成发布后问答恢复 |

| 真实模型 | 放在独立验收批次，记录模型标识、资料样例和人工核对结果，明确区分真实模型与合成夹具 |

### 摘要笔记

在独立 V4 库覆盖：无发布摘要时 409，并发 8 次保存时 1 个 201 与 7 个 200，UUID 与快照一致；打开同一笔记、刷新与重启后仍可读取。浏览器点击有效引用应高亮并聚焦原句；完整证据 ID 不匹配时显示错误，禁止按同一时间区间猜测位置。

### 单字幕检索基线

`TranscriptRetrievalBenchmarkTest` 从固定 SRT 和标签生成逐题前五候选。先核对标注引用的轨道和序号有效，再按原词、同义改写、同资料多证据及两类无答案题对比结果。合成基线用于回归和归因，完整质量门槛按独立发布题集测量。

### 只读证据检索与回读

使用有相同关键词的独立库资料，仅选其中一份时验证候选归属。按完整证据 ID 回读时核对原句、当前版本和定位字段。更换资料或版本应返回 `404 SOURCE_EVIDENCE_NOT_FOUND`，无需调用模型；无命中返回空数组。浏览器校验窄屏、错误后重试和刷新定位。此处校验检索范围与契约，发布题集另评估召回质量。

只读研究原生协议以 Python 离线夹具检查匹配的调用 ID、重复与并行调用边界、非法参数、证据变化和最终引用。隔离 HTTP 对照走真实 Java 读取合成资料。模型步骤、端到端真实供应商、工作区隔离与恢复的发布验收仍按本页 Agent 门槛执行。

Web 研究验收从资料库提交显式选择。正常回答显示已完成工具轨迹和当前原文引用，越界失败保留已完成步骤、不给出答案；修改问题后允许重试。用窄屏检查页面与焦点，并从引用链接刷新验证定位。

研究历史使用独立 PostgreSQL 应用 V7，核验正常终态与快照原文回读、失败不写入、工作区条件和模型零调用。实际浏览器保留记录链接，在 Java 重启后刷新，核对同一 UUID、同一轨迹及引用原句。

V8 重复提交对照使用合成模型阻塞首个请求。在首个请求仍执行时，同键第二次返回 409；首个请求提交后，同键返回同一记录 ID；同键改写输入返回 409。核对模型入口调用一次、数据库只有一条历史及终态发布失败时快照回滚。浏览器另模拟响应丢失后用原键重试。

V9 在隔离库仅推进单条夹具请求的截止时间，验证超时返回的旧执行不能发布，快照回滚且原键不再调模型。上游超时对照验证同键返回结果未知，新键可以显式重跑。浏览器使用合成夹具验证「查看最近研究」只读及明确重跑时切换 UUID。

V10 验证无效授权、非法资料、乱序、重复与过期回调。检查点提交失败时 Python 停止下一次模型调用。隔离模型在搜索后注入故障，原键重查应读回同一只读轨迹；正常运行的最终轨迹与数据库一致才发布。

V11 在原检查点回归上核验版本、入库参数和剩余步数。保持步骤相同，只改已确认的检索词应返回 409；只传入不一致的剩余步数应返回 400。

V12 验证输入绑定、同一父请求仅一个直接续跑、新键重放和旧证据失效。浏览器从未知状态点击续跑，结果保留原搜索调用 ID，后续步骤以剩余预算执行。

V13 验证 GET 恢复原输入与轨迹、读取过期状态不写库也不调用模型、父链接只指向一个子请求。浏览器刷新未知结果，确认恢复问题和资料后再手动继续。

研究成果流验证首次与重复创建、修订号冲突、刷新读回和 UTF-8 Markdown 下载。核对编辑前后的证据 ID 相同、旧版本编辑不覆盖新稿、界面引用仍能回到原文。字幕摘要笔记使用原有路由。

后台摘要使用隔离库验证入队去重、限流失败、原任务重试和已过期尝试无法发布。浏览器从字幕入口提交，刷新任务中心后手动重试，最后必须打开持久化摘要并定位引用。

### 个人资料收藏

在独立 V5 验收库验证默认未收藏、显式布尔值校验、未知资料 404、并发同值 PUT 的唯一性、取消后原文可读。Web 验证仅收藏可与标题和类型叠加，出错后保留状态可重试，刷新与 Java 重启后仍可回读。

### 跨字幕问答

选取 2–3 份字幕，覆盖同毫秒不同原句、模型引用未选资料的拒绝，以及刷新后的版本校验。工程回归可用合成供应商，真实比较质量按发布题集验收。

### 本地视频预检

使用 FFmpeg 合成有视频和音频的 1 秒 MP4、纯音频 MP4 和 3 秒 MOV。用真实 FFprobe 核对毫秒时长、编码和分辨率，应用 2 秒测试上限时 3 秒文件返回 422。将纯文本命名为 `fake.mp4` 并提交，必须得到 `VIDEO_INVALID`。从正式页面验证错误后更换文件可以成功，资料列表及任务数不变。共享环境上线前另测进程超时、并发饱和、隔离及清理告警。

### 本地视频受控落盘

使用独立 PostgreSQL 和临时本机卷，设置 `CITEWEAVE_VIDEO_STORAGE_TEST=1`，并明确把 `DB_NAME` 指向独立验收库。并发提交同字节不同文件名，要求一条 201、一条 200、同一个记录 ID 和一个媒体对象。坏文件返回 422 且不产生对象，未知 ID 返回 404，重启后详情可读并与磁盘 SHA-256 核对一致。页面从预检进入保存，刷新后只显示一条记录。以后采用共享部署时另验工作区权限和卷恢复。

### 本地视频字幕绑定

导入真实合成的 1 秒 MP4。上传 100–900 ms 字幕时返回 201，换名重试返回 200 和相同资料 ID，新正文允许创建独立轨道。将结束区间改到 1001 ms 返回 422，轨道和资料数量不变。刷新字幕工作区，从资料详情核对视频 ID、文件名和原始毫秒。用合成模型夹具验证摘要中的引用可定位回该轨道。

### 后台本机转写

在独立 V18 库中以真实中文样本验证网页提交、离线 CPU 处理、刷新读回和机器字幕标记。模拟 worker 拿到有效字幕时租约已经失效，旧尝试不得留下轨道；重试后尝试号加一且只有一条机器轨道。没有音轨的请求不入队。模型吞吐、并发实例资源和压力边界按部署环境另测。

### 版本化词面索引

在独立 V19 库对比 42 道冻结题的证据 ID、原文、位置与排序。并发首查应只生成一代完整版本。构建失败时不能留下版本行或影响已提交代。源内容变化后查新版本，旧词不能从旧索引漏出，命中按完整证据 ID 回读原文。正式页验证无命中、文档和字幕混合候选、刷新和重启。词面相同的回归不作为语义召回率提升依据。
