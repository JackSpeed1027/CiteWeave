# 研究 Agent、记忆与上下文规划

状态为待实现，目标版本为 2027-01-15。用户在同一工作区比较文档和字幕，追问“展开第二个分歧”，隔天在新会话问“上次还有哪条没核实”。两次回答都应能打开当时有权访问的原始证据。首版限定为单 Agent、两种只读工具、用户确认的研究记忆。资料库负责保存原文，记忆负责找回研究进度。

2026-11-23 已实现两种只读动作所需的 [Java 证据查询接口](../development/API_REFERENCE.md#查找和读取证据)。当前适用本机个人资料访问边界。Agent 接入时仍需由可信会话确定授权范围，对每次工具调用独立校验，并落实步数预算和轨迹。

同日补齐 [Python 工具回合](../development/API_REFERENCE.md#只读研究内部接口)。隔离夹具通过 Java 真实读取，覆盖检索、两次证据回读与越界中止。固定范围目前来自可信本机调用方，只有读取成功的证据可被引用。真实目标模型、正式会话授权、检查点和长期记忆仍待验收或实现。

正式 Web 的[单次只读研究](../development/API_REFERENCE.md#web-单次只读研究)接入 Java 资料预检、回答引用复核与运行轨迹。正常终态分配 UUID，并写入 [PostgreSQL 研究历史](../development/API_REFERENCE.md#最近研究与详情)。读回时由 Java 用原证据 ID 查当前版本。失败和运行中的步骤仍是临时状态，后续需定义会话身份、执行检查点和恢复状态。

V8 增加研究请求认领与完成关联，已发布结果可按同键重放。运行阶段只有请求状态，步骤尚未持久化。若工作进程退出，未来需增加租约、检查点以及上游结果未知时的处理语义。

V9 增加固定发布期限及结果未知状态。超期的执行不能再写入结果。有键请求的上游超时或通信失败会提示用户先查历史，再决定是否发起新请求。续租、检查点和自动恢复仍待接入。

V10 保存已完成工具的检查点轨迹，并在最终发布时校验快照与轨迹一致。同键确认状态时可读回这些步骤。检查点仍须补齐模型消息和预算，才能安全续跑；续租和接管待实现。

V11 同步保存结构化工具参数与剩余工具步数。后续可按已确认步骤重建工具消息，证据原文继续由 Java 回读。模型轮次、令牌预算计量、重新授权与恢复执行待接入。

Python 已提供只读重建预检，按原证据 ID 和快照顺序恢复工具消息及已读证据集合。证据已经失效会停止。接管后的权限检查、按原模型轮次续跑和令牌成本计量仍待接续。

V12 支持本机个人空间手动续跑。用新执行键、原输入和原检查点绑定一次直接续跑。重建读取失败时，后续模型调用不会发出。自动接管、独立用户身份和令牌计量待接续。

V13 提供有键请求的只读恢复链接。刷新取回问题、资料和轨迹。完成请求可打开历史，父请求可找到已创建的续跑。

## 应用职责与计划中的契约

| 对象 | 写入与读取规则 |
| --- | --- |
| 会话与轮次 | Java 保存用户、工作区、选中资料版本、问题、回答、引用和有序轮次。前端提交请求键和预期会话修订号。相同提交返回原轮次，冲突提示刷新。刷新和登录后按权限恢复。 |
| 运行与工具步骤 | Python 以当前问题、会话状态、可用证据和工具定义请求模型。工具为检索资料和读取指定证据。Java 从可信会话注入身份与授权范围，校验工具、参数、返回条数和来源版本。Python 将对应调用 ID 的结果回送模型，由模型决定继续、回答或说明证据不足。 |
| 检查点 | Java 在事务中记录运行号、尝试号、已完成步骤、工具调用 ID、结果引用、剩余预算和状态版本。恢复时校验租约、版本、权限和取消状态。对已确认的调用复用有效结果；供应商已接收但响应丢失时标为结果未知，保留已完成步骤并提示用户决定是否再次消耗额度。 |
| 长期记忆 | 建议项含结论或未决问题、形成时间、来源会话及证据版本。Web 提供查看、确认、更正、撤销。Java 写入修订与生效状态，更正替代旧修订，撤销立即排除召回，历史笔记仍保留。普通外部资料和模型输出不能自行确认。以个人在该工作区内可见为首版默认。 |
| 压缩快照 | Python 产生候选摘要，Java 记录覆盖轮次、来源修订、证据 ID、压缩策略和 Prompt 版本。快照是可重建的派生数据。撤销记忆、权限变化或来源修订失效时，连同相关缓存和检查点上下文重新过滤或重建。 |

上述对象是实施约束。实现时以新增 Flyway 迁移、版本化 DTO、样例、错误码和双方契约测试交付。正式接口目录仅登记已实现端点。Python 通过受限业务接口访问必要数据。Java 写入最终回答前复核引用、访问权限和运行状态。跨来源事实回到原始版本验证，用户自己提出的未决问题可以引用会话轮次说明出处。

## 如何决定下一次模型调用带什么

1. 计算可用输入额度，用已配置的模型窗口减去输出预留和安全余量。估算完整序列化请求，包含工具 schema、系统指令、消息封装及工具返回。可用模型计数器优先，替代估算需用中文与长字幕校准。每次调用前重新检查。
2. 优先装入系统约束、当前问题、仍有效的用户要求、选择的资料范围和最近完整交互。保留模型工具请求和返回之间的配对。早期轮次按结构化要点组织，长工具结果换成可授权回读的引用。对于“第二点”之类的指代，保留对应回答条目及证据关系。
3. 同一用户同一工作区内，先按生效状态、权限及选中范围筛选长期记忆，再按相关性取有限条目。相关度不足可空召回。答时间问题时区分讨论时间、事实发生时间和修订时间；新旧结论有冲突时给出版本和出处。
4. 预计超过输入预算时自动压缩较早的完整轮次。固定保留目标、用户约束、已核实结论、证据锚点、冲突和未决问题。压缩调用本身也要分段并计入总预算。校验结构、来源、覆盖边界和关键事实后，在会话版本一致时发布快照。
5. 失败时沿用有效快照或用确定性裁剪缩短旧工具结果，再次核算。若必留内容单独就超限，展示缩小资料范围或问题的入口。每次运行配置有限的步数、总 token 和总时间；超出、循环、取消或授权失效都产生明确终态。日志记录模型、耗时、用量、压缩前后计数、工具状态与请求 ID，默认省略原文、密钥和私密记忆正文。
