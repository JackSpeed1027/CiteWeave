### 优先级判断

- **产品目标保持一致，开发顺序出现偏移。** 研究可靠性直接服务于原型的失败重试和刷新恢复。V7–V13 连续投入到单次研究的历史、去重、截止时间、检查点、续跑与刷新，主要补强了一条研究路径。原型最关键的成果流仍只在字幕摘要上闭环。
- **下一增量优先完成已有研究结果的复用。** 从研究记录创建可编辑 Markdown 笔记，以经校验的引用作为初始来源。验收走真实页面，完成编辑、刷新读回、导出与引用核对。该增量可以用现有合成环境，无需等待真实模型。
- **并行补真实证据与主要素材。** 真实模型额度和已授权多 P 素材可用时，集中验收字幕、真实摘要、引用、笔记这条路线。合成供应商证明链路和错误边界。真实语义质量、延迟和费用要按冻结题集另测。合成单字幕词面基线 Recall@5 为 23/30（76.7%），仅作为评测对照。见[评测记录](../quality/BENCHMARK.md)。
- **随后把任务中心与真实导入或索引绑定。** 至少一个任务能从入队走到完成，失败后可恢复，完成可打开原资料。正式工作区权限和索引版本仍按原 P0 验收，持续推进。复杂外部集成和进一步研究自动化按原排期评估，优先级不超过主链路的缺口。
