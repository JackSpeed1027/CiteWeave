# CiteWeave 正式开发计划

起点为 2026-11-20，交付目标为 2027-01-15。以已验收的原型为前端体验基线，Java 保留现有资料与字幕实现，Python AI Engine 作为独立工作流推进。每日安排以用户投入 4–6 小时为上限，前端设计、实现和回归由 Codex 承担，用户只做体验验收。每周按五个主要工作日、约 20–25 小时安排用户学习、代码走读、实验和 30–45 分钟验收，其余时间可用于缓冲。

## 并行与汇合

| 工作流 | 职责 | 第一批可独立验证的产出 |
| --- | --- | --- |
| Java Core | Source、视频导入、字幕与引用定位、资料版本、任务、笔记与收藏 | Bilibili 输入归一化和分 P 契约；本地视频元数据；事务、Flyway 与错误回归 |
| Python AI Engine | 供应商调用、上下文预算、可验证的摘要、检索与 Agent | 供应商客户端契约、合成证据样本、摘要结构校验、模型失败测试 |
| Web | 将原型流程转为逐条可验收的正式页面 | 统一导入和任务状态；资料工作区能读真实字幕；按契约接摘要和引用 |
| 汇合 | Java 仍是业务主数据入口。Python 使用版本化证据，返回草稿与引用 | 一次贯通「上传真实字幕 → 读取证据 → 生成摘要 → 跳转时间轴 → 保存笔记」 |

首批契约在实现时随代码和示例维护。Java 输出证据标识、资料与内容版本、正文及定位类型，时间戳用整数毫秒。Python 返回草稿、证据标识、是否截断及失败分类。Web 根据稳定状态字段渲染，Java 校验返回引用属于本次证据集合。首批字段经过双方测试后再扩展。缺少真实模型配置时，可以在独立测试中用明确标记的合成夹具，真实模型验收单独记录。

正式集成从本地 `develop` 开始，Java、Python 和 Web 分别用短生命周期功能分支推进。变更共享契约时先交付示例和契约测试，再并行接入生产方与消费方。每个阶段至少核对一次两边的契约测试、样例及失败语义，能独立构建的功能优先合入，在汇合点执行端到端验收。

P0 保障的首要闭环是资料导入、版本化证据、真实摘要或问答、引用、笔记与导出。平台字幕获取受授权与可用性影响，保留手动上传路径。P1 用实证展示后端与 Agent 技术深度，任何性能指标均来自可复现实验。避免同时引入多种运行依赖，每个增量保留运行和回退说明。

## 设计模式与对应实验

| 机制 | 用在哪里 | 选择理由与替代 | 小实验 |
| --- | --- | --- | --- |
| Adapter | Bilibili、模型供应商 | 把平台协议映射为稳定业务契约。单平台早期用一个具体类足够，出现替换或隔离需要时再引入接口 | 用本地夹具替代远程响应，比较调用者看到的分 P 和错误字段 |
| Strategy | 平台字幕、用户字幕、授权音频 ASR | 复用输出契约并显式表达优先级。只有一个渠道时采用直接调用 | 同一视频切换有字幕、缺字幕和用户附传，记录哪条路径被选中 |
| 有限状态机 | Java 导入任务 | 用状态转换表表达合法动作与重试边界，必要时用 SQL 条件更新。状态对象类层级等有实际复用场景再考虑 | 两个 Worker 同时尝试领取一个隔离任务，记录状态、受影响行数与唯一执行者 |
| Pipeline | 解析、字幕、分块和摘要 | 处理阶段职责独立，按输入与版本复用结果，避免后续重算全部文件 | 修改摘要参数后比较 ASR 与摘要阶段的调用次数 |
| Repository 与 Transactional Outbox | Java 业务数据与跨进程发信 | Repository 隔离 SQL，Outbox 保存事务内发布意图。已有 JdbcClient 仓储继续工作，Outbox 等异步用例实际出现再引入 | 在隔离环境让发布进程中断，观察重启后重投递与业务幂等 |
| 显式工作流图 | Python 复杂多步研究 | 节点输入输出清晰，Checkpoint 可恢复。普通摘要保持固定流程 | 在已完成检索后故意停一轮，再从检查点恢复，比较工具执行记录 |

先阅读代码再设计实验。Codex 准备可反复执行的样例、命令和观测记录。用户亲自执行关键动作，描述观察和推理后再一起分析。实验成果采用实际输出，学习题见 KNOWLEDGE_CHECK。
