# 架构决策

## 正式开发的两个运行时

Java Core 继续处理资料、业务事务和权威状态，Python Engine 用来独立验证模型供应商、证据预算和研究流程。采用独立启动与简单的版本化 HTTP 契约。把模型调用全部留在 Java 会更快完成一次同步联调，但会减少 Python 运行时独立验收和后续复用的空间。两个进程增加启动与错误处理成本，首个联合功能将明确超时、错误分类和证据校验。回环健康检查仅作为本地进程验证。

- **本地 Monorepo**。前后端、迁移、基础设施和验收样本可在同一份版本中同步评审。前后端分别构建，通过 Vite 代理联调。
- **MyBatis-Plus 与 Flyway**。Java 主代码的持久化通过 MyBatis Mapper。常规单表读写使用 BaseMapper 和类型化条件。分 P、分页证据和收藏的关联查询，以及并发去重、JSONB 和检查点条件写入由 Mapper XML 表达。Flyway 继续维护数据库版本，历史迁移保留。
- **摘要和任务终态同事务提交**。模型调用在事务外完成。摘要插入后，在同一数据库事务校验原资料版本、任务尝试和租约，再提交成功状态。若最后一步失败，未提交的摘要一起回滚。已有同版本摘要可直接复用，任务仍需通过条件更新。
- **本地视频采用内容寻址存储**。上传暂存与正式对象处于同卷。探测通过后以 SHA-256 命名并发布完整对象，数据库按工作区和摘要唯一约束收敛并发记录。对象先写、数据库后登记，失败重试复用同内容对象。服务端媒体目录与桌面 Agent 的用户输出目录分别授权。
- **词面索引按资料和分词版本生成**。沿用 Java 分词，PostgreSQL 用词项数组交集过滤、交集数排序。版本行和片段在同一事务可见；待构建版本不会替换已提交代。现有原文材料不可变，新一次查证只读当前资料版本。 [PostgreSQL GIN 词项数组支持](https://www.postgresql.org/docs/17/gin.html#GIN-BUILTIN-OPCLASSES)
- **同步解析、一次写入**。约束上传体积、PDF 页数和提取文本长度。解析失败时数据库没有写入。并发插入使用数据库标识生成，重复提交目前会得到独立资料。
- **PDFBox 与 UTF-8 文本处理**。支持 PDF 文本层并保留文本和字幕布局。异常文件和不可提取内容返回明确错误。
- **React + CSS 设计系统**。用 CSS 变量管理色彩及控件，Lucide 提供一致的图标。四页共享布局、按钮、状态和列表组件，后续可按复杂度增加组件依赖。
- **由现有原文派生字幕时间轴**。先统一时间轴和拒绝无效新上传，沿用原文存储与单条 INSERT。代价是在读取时间轴时重解析。出现多轨道、版本化引用或高频检索后，才新增持久化的轨道和片段。
- **平台 Adapter 与获取渠道隔离**。Bilibili 按分 P 预览，与本地文件一路汇入时间轴。候选库、匿名访问与降级条件见 [视频方案调研](VIDEO_RESEARCH.md)。
- **预览与写入分步**。Java 预览以固定公开端点查询已规范化的编号，在本地选择分 P。改用直接转发浏览器链接会扩大网络访问边界和前端对平台协议的依赖。当前代价是短链需先打开视频页再复制链接，预览的每次请求均依赖平台状态。
- **模型调用与证据校验分步**。Python Adapter 管理供应商请求与失败分类，摘要工作流负责验证结构和引用。使用注入的 HTTP 客户端，避免依赖真实模型即可验证协议和网络失败。供应商输出质量和业务期间的重试另行验收。
- **研究历史保存终态与证据标识**。Java 在模型返回且引用校验成功后，用一次 INSERT 保存问题、范围、回答和轨迹。快照引用原资料的版本化 ID，详情按当前访问边界及版本回查。这样研究记录无需再生成，正文也只有一个权威来源；原证据不可用时详情会提示错误。运行中间状态、重复请求去重与崩溃恢复由后续执行生命周期设计处理。
- **研究请求的认领与结果发布**。V8 用工作区与请求键的唯一约束认领，独立语句先提交再调用模型。发布时在短事务中同时写历史和请求终态，响应丢失可用原键回读。这样数据库不会在模型耗时期间持有事务；代价是崩溃可能保留尚未发布的处理中状态，后续由租约与检查点处理。
- **过期执行与不确定结果**。V9 用数据库时钟给研究请求设固定期限，发布必须同时匹配处理中状态和有效期限。超时或通信异常可能发生在上游已接受模型调用之后，于是关闭原键并标记结果未知。期限是发布边界，自动接管仍需独立解决步骤持久化与重复调用。
- **先确认步骤，再推进模型**。V10 将最多三步的累计轨迹存到请求行，用旧轨迹和有效期限作条件更新。重复回调幂等，最终发布要求轨迹与数据库一致。每个工具多一次本机数据库往返，换得故障后可查的已完成动作。当前只保存工具及证据标识，恢复模型上下文需要另行设计。
