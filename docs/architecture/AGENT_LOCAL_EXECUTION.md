# CiteWeave Agent · 本机工作目录与外部连接器设计

状态为待评审设计。仓库已有只读研究工具、检查点、版本化证据和后台任务。本设计复用它们，增加本机授权、文档操作、交付与外部动作的执行层。文件、视频和邮件通过相同的任务与交付模型组合。实现前按现有计划确认排期及公开发布范围。

## 成品体验

安装 CiteWeave Desktop，登录后在会话顶部设置「工作目录」和「保存位置」。目录由系统选择器授权。界面显示当前电脑、输入范围、输出位置及联网策略，可临时为单次任务换目录。用户可保存常用设置、回到旧会话继续处理，并随时解绑目录或邮箱。在 Web 上，用户仍可上传资料、预览和下载，也可查看桌面任务的状态。在桌面连接可用时，由登记的设备执行本机动作。

| 用户指令 | 系统执行 | 完成凭据 |
| --- | --- | --- |
| 把资料文件夹里的课程截图整理成逐图笔记，保留原文档布局 | 查明所选文档结构，按图片出现位置提取证据，生成逐条可编辑的插入计划，预览并保存副本。若用户选择修改原件，展示逐文件差异、单独确认并保留恢复版本 | 每个文件的处理状态、成品路径、输入与产物版本、跳过项和恢复入口 |
| 总结这三个视频，生成一份对比报告，保存到我的课程输出目录 | 复用视频、字幕和引文工作流，按用户指定格式生成报告，由桌面存入已授权位置。缺字幕或模型不可用时，显示对应视频的可恢复状态 | 报告路径、引用回跳、每个来源的结果 |
| 把刚做好的报告发给同学，邮件简短一点 | 生成标题、正文及已生成的附件，展示实际收件人和发件账户。用户确认本次发送后，用已连接的邮箱提交 | 发送账户和时间、服务商回执、失败或结果未知状态 |
| 整理这些本地 Markdown 和 Word，生成复习提纲并发给我 | 同一会话组合读取、检索、编辑、导出和发送。先处理内容，保存成功后才开放该版本作为邮件附件 | 一个任务下展示草稿、完整文件、邮件分别处于什么状态 |

未识别的格式给出可处理部分与失败原因。文档能力按格式公开，例如 Word 正文的插入、Markdown 块替换、PDF 页图读取与派生产物。保留布局的编辑成本随格式增加，复杂浮动对象、宏、签名文档和同步文件夹需要各自的支持规则。对未知文档结构，用户可预览保留原件的导出方案。

## 系统职责与技术选型

| 模块 | 职责 |
| --- | --- |
| React Web 与 Desktop | 复用会话、研究、任务中心、证据和笔记页面。桌面新增原生目录选择、文件差异、进度托盘、权限中心和系统通知。浏览器保留上传下载和支持环境中的文件选择 |
| Java Core / PostgreSQL | 会话、账号和设备归属，保存目录绑定的逻辑标识、工作区授权、版本、任务、检查点和动作回执。任务有并发额度、租约、取消与恢复。所有状态据真实结果更新 |
| Python AI Engine | 结构化计划、检索、视觉或 OCR 调度、摘要、编辑建议、工具选择、提示词与模型预算。工具描述接受受控资源引用，返回版本化草稿及可核验证据 |
| Desktop 本机执行器 | 受信任的 Electron 主进程持有目录映射和最小化的本机接口。独立的受限进程处理文档、图片与媒体。持久化本机动作日志，支持托盘后台运行、启动恢复和真实文件提交 |
| 邮箱连接器 | OAuth 授权、凭据隔离、草稿渲染、确认后发送、回执与账户撤销。每个连接器只接受其已声明的操作与格式 |

桌面选 Electron，主要为了沿用 React 和 TypeScript，并使 Windows 安装与桌面交互可单独验收。打包的本地页面通过窄的 preload 接口调用主进程。启用上下文隔离、渲染沙箱、严格 CSP，关闭页面 Node 权限，校验 IPC 来源和参数，外来网页或文档间接渲染。桌面连接 Java 用已认证的出站连接，绑定账户、工作区、设备和有效期。设备启动和操作系统权限均由用户控制。电脑关机或离线时显示等待设备和最后心跳；主进程运行而窗口关闭时可继续执行已获准任务。个人可以先采用同一电脑的本机部署，团队版可在远端部署 Java，桌面仍在本机按授权执行。 [Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

工具目录描述输入输出 schema、能力类别、版本、需要的授权、审批策略和重试语义。转换器通过格式 Adapter 承担提取、定位、差异和导出，邮箱 Provider 适配器实现连接、发送和回执。新增能力通过工具注册、验证器、执行器和契约测试接入。已有 Java 任务和研究检查点可提供持久化基础。若采用 LangGraph，用于规划和暂停恢复；文件提交与邮件回执仍使用业务日志。 [LangGraph 持久执行](https://docs.langchain.com/oss/python/langgraph/durable-execution)

## 工作目录、数据与权限

- **授权对象。** 一次授权明确用户、设备、目录、动作、任务范围和有效期。可设为一次任务、当前会话或可信工作区的可撤销授权。会话记住别名和资源版本，桌面保管实际目录位置。恢复任务时重新检查设备、授权、输入版本与已完成动作。
- **读与保存。** 默认把明确选中的目录作为输入范围，输出目录单独授权。用户可以在启动任务时一次确认「将产物写入这个输出目录，遇到同名用新名字」，随后同一批按该范围提交。修改既有文件时展示具体路径和差异，重新核对内容版本，并保留恢复副本。对无法保证安全替换的卷或打开中的文件，生成新文件并告诉用户冲突原因。
- **真正的文件边界。** 本机执行器用标识查实际文件并在打开、创建和提交时核对目录归属、文件身份及版本。Windows 对 junction、符号链接等重解析点走受控规则。先用本机文件句柄与替换能力做可行性验证，明确支持的文件系统和并发语义。字符串前缀校验不足以保证路径隔离。格式解析器限制嵌套、展开大小、进程资源和执行时间，禁用宏执行，文档或截图里的文字不能授权工具。 [Windows 文件替换 API](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)
- **外部数据。** 目录读取、发送给模型、邮件发送是独立授权。显示供应商、内容类别与接收方。支持用本机解析、OCR 或自托管模型减少外发；相关模型可用性、质量和性能独立验收。服务器持久化工作区内有权保存的产物与引用；本地专用模式的源文件和凭据留在用户设备。连接器凭据由其执行端的凭据存储保管，模型和渲染页面只拿逻辑 ID。
- **外部动作。** 邮件连接不等同于发送批准。每次发送展示账号、收件人、主题、正文和附件，确认绑定该动作和内容摘要，修改后重新确认。用 OAuth 发送权限，不要求读取整个邮箱。桌面使用系统浏览器完成其支持的 OAuth 流程，公共客户端按供应商要求使用授权码与 PKCE。Outlook 可采用 Graph 委托发送权限，Gmail 采用专用发送 scope，公开应用验证与租户同意单独排期。 [原生应用 OAuth](https://www.rfc-editor.org/rfc/rfc8252) · [Graph 发送权限](https://learn.microsoft.com/en-us/graph/api/user-sendmail?view=graph-rest-1.0) · [Gmail 权限](https://developers.google.com/workspace/gmail/api/auth/scopes)

## 恢复与可追溯交付

1. **计划及检查点。** 每次运行保存目标、资源版本、工具步骤及预算。幂等键绑定任务与动作，执行者凭租约认领。解析和模型步骤可以按文件或片段恢复，已完成的输出按版本复用。
2. **本机提交。** 生成临时产物并验证能重新打开。批准后核对路径、目标版本与内容摘要，再完成提交。提交前持久化意图，提交后保存路径与摘要；进程中断后对账，核实同一动作是否已执行。批量操作逐文件记录结果，允许失败项单独重试或在确认后从备份恢复。
3. **邮件提交。** 在网络请求前持久化这次发送。收到服务商接受回执时展示「服务商已接收」。Graph 的 202 不代表已投递。若请求发出后断线且无法查证，标记「发送结果未知」并要求用户核对。重启或续跑不自动再发这封邮件。服务商明确拒绝和无法确认分别记录。 [Graph 发送响应](https://learn.microsoft.com/en-us/graph/api/user-sendmail?view=graph-rest-1.0)
4. **操作视图。** 每个完成项能打开文件、查看差异或复制回执。用户可以取消未提交动作、重试可重试部分和撤销授权。回执只保存排查所需的账号标识、版本、时间和状态。服务端日志省略 OAuth 凭据、原文、邮件正文与本机绝对路径。

## 验收线、工期与外部依赖

成品验收使用新安装的 Windows 用户账户。测试同目录连续使用、切换目录、跨工作区拒绝、退出重启、锁屏/断线恢复、撤销授权和权限提示。三条业务链路为多种文档批处理、视频报告保存、生成后邮件发送。用同一套任务、工具与权限契约跑通。负向测试涵盖链接越界、源文件并发修改、同名冲突、部分输出失败、保存过程中退出、撤销邮箱、收件人变化使确认失效、提交后断线且不重发。用户预览、实际落盘、重新打开、接收测试邮件分别记录。公开发行还需安装包签名、升级与回滚、可支持的 Windows 版本及连接器合规验证。

| 工程段 | 预计独立工程日 |
| --- | ---: |
| 桌面壳、目录授权、设备登录、持久化本机操作日志 | 7–11 |
| 通用工具目录、任务编排、恢复、审计与审批 | 8–12 |
| 文档、图片和视频产物适配，预览、批量处理及文件提交 | 7–11 |
| 一个真实邮箱供应商及回执、撤销和故障处理 | 4–7 |
| 安装、升级、Windows 文件边界和端到端回归 | 6–9 |
| 合计 | 32–50 工程日 |

估算假设一人每天 4–6 小时、每周五天，优先 Windows，复用现有 React/Java/Python，覆盖有限但完整的文件格式及一个邮箱供应商，且模型和测试账号可用。按约 8–12 周日历安排含缓冲。供应商审核、企业租户同意、分发签名与不熟悉的文档格式可能延长时间。多操作系统与多个正式邮箱供应商应独立重估。当前 2027-01-15 计划仍需完成真实模型、授权隔离与索引验收；若要纳入完整桌面交付，应取舍原排期或另设交付日期。

开工顺序先并行验证最难返工的两条依赖。Windows 上验证取消授权与重启后恢复、在目标文件被改动时阻止覆盖；邮箱用授权测试账号验证发送、撤销以及请求发出后响应丢失。验证结果决定文件系统支持范围和邮箱选型。随后把通用能力连成两条不同业务的端到端链路，最后再扩充格式与体验。首项验收验证技术可行性，最终交付仍按本节的完整标准验收。
